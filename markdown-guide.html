Markdownの書き方と .md ファイルの役割

← トップに戻る

Markdownとは

テキストに簡単な記号を加えるだけで、見出し・太字・リストなどの書式が表現できる軽量な記法。 GitHubでは .md ファイルを自動でレンダリング（見やすく整形して表示）してくれる。

HTMLとの違いは、記号がシンプルで読み書きしやすい点。ただしHTMLほど細かい制御はできない。

基本的な書き方

見出し

# の数で見出しのレベルが変わる。

# 大見出し（h1相当）
## 中見出し（h2相当）
### 小見出し（h3相当）

段落・改行

普通に文章を書くと段落になる。改行したいときは行末にスペースを2つ入れるか、空行を1行入れる。

1段落目の文章

2段落目の文章

太字・斜体

**太字**
*斜体*

リスト

- 箇条書き項目1
- 箇条書き項目2

1. 番号つき項目1
2. 番号つき項目2

リンク

[表示するテキスト](URL)

例：

[GitHubへ](https://github.com)
GitHubへ

コード

1行のコードはバッククォート（`）で囲む。

`git status`

複数行のコードはバッククォート3つで囲む。言語名を書くとシンタックスハイライト（色付け）される。

```bash
git add .
git commit -m "メッセージ"
```

区切り線

---

代表的な .md ファイルとその役割

README.md

リポジトリの「説明書」。GitHubのCodeページを開くとファイル一覧の下に自動で表示される。 プロジェクトの概要・使い方・セットアップ手順などを書くのが一般的。

リポジトリを公開するときは、まずREADMEを書くと見た人に伝わりやすい。

CLAUDE.md

AIアシスタントの「Claude Code」に向けた指示書。このファイルがあるフォルダでClaude Codeを使うと、 書いた指示が自動で読み込まれ、会話のたびに毎回説明しなくてもよくなる。

例えば「説明は日本語でお願いします」「シンプルな構成を保ってください」といったルールを書いておける。

その他よく見かける .md ファイル

  • CHANGELOG.md：バージョンごとの変更履歴をまとめたもの
  • CONTRIBUTING.md：そのプロジェクトへの貢献（コード提供など）のルールを書いたもの
  • LICENSE.md：そのコードをどう使っていいかのライセンス条件
